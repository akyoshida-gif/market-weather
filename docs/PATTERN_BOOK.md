# パターン台帳（武器庫）とデモトレードの運用

状態：**合意済み（2026-10-30）**　作成 2026-10-30
検証計画（VALIDATION_PLAN.md）の結果を、実際の相場でどう使い、どう改善していくかを決める文書。

---

## 0. 考え方（オーナーと合意）

- **黄金のパターンを1つ探すのではない。** 過去にうまくいったことと、これからうまくいくことは別。どのパターンもいつかは効かなくなる。
- **武器庫を作る。** うまくいきそうなパターンを複数持ち、それぞれの得意・不得意な場面（edge ケース）を把握し、互いに補い合うように使う。
- **効かなかったら捨てる、ではない。** なぜ効かなかったかを考え、次のどれかを判断する。
  - ほかのパターンと組み合わせれば使えるか
  - 別のパターンの弱いところを補えるか
  - そもそもダメか
- **改善するのは Claude 自身。** 実際の相場でデモトレードし、結果を分析して直していく。

## 1. パターン台帳

パターンごとに次を記録する（`config/strategies/` と R2 の `paper/` に保存）。

| 項目 | 内容 |
|---|---|
| 名前・型 | 例：短期の反発、上抜け、長期トレンド、市場全体のタイミング |
| 条件 | シグナルの条件（はい・いいえの条件、数値の区分、市場全体の条件の組み合わせ） |
| 出どころ | 方法Aのどの探索で見つかったか、判定（主力候補・新しい傾向・観察） |
| 保有期間・損切り | 方法Aで選ばれた損切りの置き方と、保有期間 |
| 強い相場・弱い相場 | 相場の状態ごとの成績（S&P 500 のトレンド、VIX、金利、原油、信用スプレッド、小型株の強さ、上昇銘柄の割合など） |
| ほかのパターンとの関係 | 同じ日にシグナルが出やすいか、成績が一緒に動くか、片方が弱い時期にもう片方が強いか |
| 状態 | 運用中（通常）／運用中（少額）／記録のみ／保留／終了 |
| 履歴 | 変更の内容・理由・日付 |

## 2. デモトレードの運用

- **同時に動かすパターンは10〜20個**（オーナー判断 2026-10-30）。
- 1つの型に偏らないよう、性格の違うものを組み合わせて選ぶ。
- 金額は確度で分ける。
  - 主力候補（長寿命）：通常の金額
  - 主力候補（新しい傾向）・観察：少額、または記録のみ
- 取引ごとに、**買った時点の相場の状態**（市場全体の数値、約400項目）を記録する。後で「なぜ負けたか」を分析するため。
- 価格がそろっていない日は処理しない（2026-10-30 の修正）。

## 3. 週1回の振り返り

オーナー判断（2026-10-30）：まず週1回。

1. パターンごとに、その週と累計の成績（R の期待値、取引数、損切りされた割合）を出す。
2. **負けた取引と勝った取引の、買った時点の相場の状態を比べる。** どの数値で差が大きいかを出す。
3. 次のどれかを提案する。

| 提案 | 例 |
|---|---|
| 条件を足す | 「VIX が高いときに負けている → そのときは見送る」 |
| 損切り・保有期間を変える | 「損切りに触れた後に戻している → 損切りを広げる」 |
| 組み合わせる | 「Aが弱い相場で、Bが勝っている → 相場の状態で使い分ける」 |
| 保留 | 記録は続け、金額は入れない |
| 終了 | どんな相場でも優位性が見えない |

4. 提案した変更は、**過去のデータで確かめてから**、オーナーの合意を得て反映する（勝手に変えない）。
5. 取引の数が少ないうちは、結論を急がない（1つのパターンで最低20取引を目安にする）。

## 4. 進め方

1. 方法Aの結果を「武器庫」としてまとめて報告する（パターンごとに強い相場・弱い相場を付ける）。
2. デモトレードに入れる10〜20個の案を出し、合意を得る。
3. 方法Aのパターンを毎日判定して注文を出す仕組みを作る（今のデモトレードは方法Aより前の戦略を使っているため）。
4. 週1回の振り返りの仕組みを作る。
